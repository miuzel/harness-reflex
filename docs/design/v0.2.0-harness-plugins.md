## 0. 结论速览

- **能力面**：pi 能复刻 10 项中的 7 项、3 项部分、0 项做不到；Claude Code 4/5/1，唯一 ❌ 是设置面板；
  DSH 自身 8/2/0（剪枝与收尾在 DSH 里也不是「满格」——剪枝靠留存契约、收尾只是 steering）。
- **代码共享**：判定面可共享 **85%–90%**；单 harness 端到端 **~78%**；第二个 harness 的新增代码只有
  **~20%–25%**（纯适配层）。所以「三 harness 共享 80%」对判定面成立，对端到端是**上限而非保证**（§2.2）。
- **状态**：Claude Code 的 command hook 每次都是新进程（CC §2.1/§2.7），**必须**有外部会话状态；
  pi 是进程内模块可放内存，但为了账本/面板同口径，两者统一走同一 `StatePort`（§3）。
- **MVP**：内核 + 状态 + `hook` 子命令 + **Claude Code 三件套的自动层**（剪枝/停滞/纠偏 active，
  收尾核验默认 observe），不含虚拟模型、思考等级、面板、pi（§4.2）。
- **建议先做 Claude Code**，理由见 §4.3：它逼出无状态 hook + 外部存储这条最难的路，pi 在其后只需薄适配。

**矩阵自检**：Claude Code 4✅/5🟡/1❌，pi 7✅/3🟡/0❌，DSH 8✅/2🟡/0❌。
唯一 ❌ 的两条依据都是「组件/终端面」的事实（CC §1.1、§6.3），不是「没找到就说不行」。
反过来，**pi 没有 ❌ 不等于 pi 更强**：pi 的 3 个 🟡 里有两个是 DSH 语义的硬缺口（收尾无 veto、账本无隔离域）。

## 2. 架构方案

规则（可用一条测试自动守住）：

1. `core/` 的 import 只允许 `core/`、`ports/`、`backend/types`；**禁止** `adapters/*`、`state/*`、`node:fs`。
2. `adapters/a` 不得 import `adapters/b`；跨 harness 的唯一共享物是 `core/` + `ports/`。
3. `state/` 可 import `ports/` 与 `node:fs`，但**不得** import `adapters/`。
4. 判定后端的选型（jev / mock / simple-jev）只由配置注入，适配层不得读环境变量决定判定语义。

### 2.2 共享内核 vs 适配层：目录与共享度量化

目标态目录（★ 新增 / 需重写；⛔ 既有，复用或微调）：

```
src/
├── backend/          判定后端（已有，不动）
├── core/             ★ 共享内核（harness 无关）
│   ├── policy.ts     ★ 三态 off/observe/active + per-turn/per-session 预算 + 失败放行
│   ├── judge.ts      ★ 一次判定 = 输入(候选/证据) → verdict；带幂等键与缓存
│   ├── prune-plan.ts ★ 剪枝**计划**（保留原文 → 产出 locator + 缩减文本），不含改写动作
│   ├── stagnation.ts ⛔ 判据复用，补「签名 + 滑动窗口」纯函数
│   ├── gate.ts       ⛔ 证据核验（fail-closed）复用
│   ├── closing.ts    ★ 收尾核验：声明 vs 证据 → {contradicted|insufficient|ok}
│   ├── evidence.ts   ★ 证据组装（工具结果 → 可核验断言）
│   ├── ledger.ts     ⛔ 追加/摘要/内存模式复用，schema 增 harness 字段
│   └── {route,score,screen,calibrate}.ts  ⛔ 原样复用
├── ports/            ★ 端口（接口 + 纯类型，零实现）
│   ├── harness.ts    事件 → 内核输入的归一，内核输出 → 动作语义（三态动作）
│   ├── state.ts      会话状态读写（含预算扣减、dedupe）
│   └── originals.ts  原文留存/还原（locator）
├── state/            ★ 端口实现
│   ├── file-store.ts 无状态进程用（Claude Code hook）
│   ├── memory-store.ts 进程内用（pi / DSH）
│   └── locator.ts
├── adapters/
│   ├── {claude,codex,agy}.ts  ⛔ 既有安装器适配，不动
│   ├── claude-code/  ★ hooks 协议编码 + mod 注册 + `.mcp.json` 生成
│   └── pi/           ★ extension 工厂 + 事件注册 + 工具注册
└── cli/index.ts      ⛔ 新增 `hook <event>` 子命令（已有空壳，见 src/cli/index.ts:260）
```

**共享度量化**（按需实现的代码行估算，不含测试）：

| 功能块 | 估算行数 | 可共享 | 说明 |
|---|---|---|---|
| 判定调度 / 三态 / 预算 / verdict 缓存 | 900–1200 | 90% | 唯一差异是「时钟 + 锁」，端口可吸收 |
| 剪枝计划 + 留存契约 | ~300 | 85% | 「怎么改写输出」是适配层的 15% |
| 停滞签名与判定 | ~250 | 95% | 纯函数 |
| 失效纠偏文本与触发 | ~200 | 85% | 注入点不同 |
| 收尾核验（声明 vs 证据） | ~250 | 80% | 裁决→动作映射三份（见下） |
| 证据组装 | ~200 | 95% | 纯函数 |
| 账本 / 路由 / 评分 / 筛查 / 校准 | ~1500 | 100% | 已有 |
| **判定面小计** | **~3600** | **≈89%** | |
| 适配层（每个 harness） | 600–1200 | 0% | 事件解析 · 输出编码 · 状态载体 · 模型设定 · 分发 |
| **单 harness 端到端** | **~4500** | **≈78%（首个）** | 第二个 harness 追加 ~20%–22% |

**结论（回答「能否共享 80%」）**：判定面 85%–90%，可以；端到端 78%，**80% 是上限**。
三处结构性不可共享，必须写三份：

1. **裁决 → 动作**：DSH 是 `agent/turn-stopping` 的 steering；Claude Code 是 `{"decision":"block"}` 硬闸；
   pi 是「追加一条 custom_message + `continue:true`」。同一个 verdict，三种动作，**不能抽成同一段代码**，
   只能抽到「ActionPlan 三态（放行/附注/阻断-或-续跑）」再由适配层展开（能再吃掉 5–8 个百分点）。
2. **状态载体**：DSH 有 per-agent `AgentState`；Claude Code 只有 stdin 的 `session_id`；pi 有进程内
   `ctx` + `appendEntry`。
3. **输出编码**：Claude Code 的 `hookSpecificOutput` 嵌套（`permissionDecision` / `updatedToolOutput` /
   `additionalContext`）vs pi 的扁平 `{block, reason}` / `{content, details}`。

### 2.3 Claude Code 载体：plugin 三件套

一个 plugin 目录同时携带三种组件（CC §1.1 确认可同装）：

| 载体 | 职责 | 能做 | 明确不能 |
|---|---|---|---|
| **mod**（`hooks/hooks.json` → `modules:["./register.js"]`，进程内） | 自动干预的**主路径**：`tool.call` deny/改写、`session.append` 改写输出、`turn.step` 设模型/effort | 状态在内存里，零 fork；可改 model/effort（CC §4.2） | 需要 v2.1.287+；WSL 桌面会话不加载；`classic.Stop` 无 block 保证（CC §7/§9） |
| **MCP server**（`.mcp.json`，stdio） | 决策**工具面**（8 个 `reflex_*` 原样） | 模型主动调用 | 纯 MCP **不能**做任何自动干预（CC §8-1），不能设模型/effort（CC §8-2） |
| **settings hooks**（`hooks/hooks.json` 的 command 类型） | **硬闸与兜底**：`Stop` 阻断、`PreToolUse` deny、无 mod 时的降级通道 | Stop 可硬阻断（CC §2.4） | 每次 fork；默认 600s 超时；默认 fail-open（CC §2.7） |

**hook 事件表**（`harness-reflex hook <event>`，契约见 §2.5）：

| 事件 | 子命令 | 读取的 stdin 字段 | stdout | 失败策略 | 内部预算 / hook timeout |
|---|---|---|---|---|---|
| `PreToolUse` | `pretooluse` | `session_id` `tool_name` `tool_input` `tool_use_id` | 有 verdict：`{"hookSpecificOutput":{"permissionDecision":"deny","permissionDecisionReason":…}}`；否则 `{}` | **F1 放行** | 300 ms / 1 s |
| `PostToolUse` | `posttooluse` | 上列 + `tool_response` `duration_ms` | `hookSpecificOutput.updatedToolOutput`（剪枝）、`additionalContext`（纠偏） | **F1 放行** | 800 ms / 2 s |
| `PostToolUseFailure` | `postfailure` | `tool_name` `tool_input` `error` | 仅 `additionalContext`（官方不支持替换错误文本） | **F1 放行** | 300 ms / 1 s |
| `Stop` | `stop` | `stop_hook_active` `last_assistant_message` `transcript_path` `background_tasks` | `{"decision":"block","reason":…}` 或 `{}` | **F3**：只有决策本身能阻断，内部错误一律放行 | 1000 ms / 2 s |
| `SubagentStop` | `substop` | 同 Stop + `agent_id` `agent_type` | 同 Stop（首发默认关闭） | **F3** | 1000 ms / 2 s |
| `SessionStart` | `sessionstart` | `session_id` `source` `cwd` | `additionalContext`（仅告知当前三态，不注入业务文本） | **F2 静默放行** | 1200 ms / 2 s |
| `SessionEnd` | `sessionend` | `session_id` `reason` | `{}`（flush + gc） | **F2 静默放行** | 1200 ms / 2 s（官方 SessionEnd 共享 1.5 s） |

失败策略定义：

- **F1 放行 + 审计**：超时/崩溃/坏 JSON → exit 0、stdout `{}`，把错误写进账本 `type:"error"`。
  不设 `onFailure:"block"`——`onFailure` 有版本门槛（v2.1.295），且判定类 hook 崩溃即阻断会把
  「反射层」变成「单点故障」。
- **F2 静默放行**：连审计都只写本地文件，绝不阻塞会话起止。
- **F3 决策式**：「能阻断」只来自子命令**正常算出**的 `decision:"block"`，不来自崩溃。
  每次 block 都记 `turnNo`，并在 `stop_hook_active === true` 时直接放行（官方用它防死循环，
  另有 8 次硬上限，CC §2.4）。

接线要点（都是官方契约约束，不是口味）：

- `if` 匹配器只订阅会产出大结果/重复调用的工具（`Bash` / `Edit` / `Write` / `MultiEdit` / MCP 通配），
  不匹配时**不 spawn**（CC §2.8）。
- `PostToolUse` 改写前必须**先把原文落盘成功**，否则不替换（复刻 DSH「没有留存就不记 saved」）。
- 多个 PreToolUse 同时改 `updatedInput` 的顺序不确定（CC §6.1），因此**我们永远不返回 `updatedInput`**，
  只返回 `deny` 或附加 `additionalContext`。
- 输出文本受 10,000 字符上限约束（CC §2.7），长证据只给 locator + 摘要。

### 2.4 pi 载体：一个 extension 包

包形态：`pi install npm:harness-reflex-pi`（或 `pi -e ./ext`），peer 依赖宿主包（PI §2.2）。
注册面：

| 注册项 | 内容 | 说明 |
|---|---|---|
| 工具 × 5 | `reflex_choice / score / route / screen / gate` | 与 DSH 宿主面一致；`route` 默认 `exposure:"hidden"`。**不注册** prune/detect_stagnation/status_ledger——pi 里这三项是自动层 + `/reflex-ledger` 命令，避免 pull 版与自动版双重干预 |
| 命令 × 1 | `/reflex-ledger [--last N] [--json]` | 读同一账本实现；`ctx.mode !== "tui"` 时降级为纯文本 |
| 虚拟模型（S5，默认关） | `registerVirtualModel({provider:"reflex", id:"auto", route})` | `route()` 内调内核路由，返回物理 `{model, thinkingLevel}`；粘性用 `request.previous/failed` 保 cache（PI §5.2） |

事件订阅：

| 事件 | 用途 | 返回/动作 | 依据 |
|---|---|---|---|
| `session_start` | 建 `MemoryStateStore`，装配置；`session_shutdown` 幂等释放 | — | PI §2.1 |
| `tool_call` | 停滞判定 → 拒绝 | `{block:true, reason}` | PI §3.2 |
| `tool_result` | 剪枝（改写 content，**同时**带 `structuredContent`）与失效纠偏（`isError:true` + 纠正文本） | `{content, details, structuredContent, isError}` | PI §3.2/§3.3 |
| `turn_end` | 回合级续跑边界（可动作） | `{entries:[…], continue:true}` | PI §4.2 |
| `agent_before_settle` | 收尾核验：不通过则追加纠偏消息 + 续跑 | 同上，**上限 1 次/回合、2 次/会话** | PI §4.4 |
| `model_select` / `thinking_level_select` | 只观察，写账本（不改用户选择） | 无返回 | PI §5.3 |
| `session_compact` / `session_shutdown` | 账本 flush + 留存 gc | — | PI §2.1 |

**「收尾只能续跑不能否决」怎么用**（这是 pi 侧最容易被写错的语义）：

1. 在 `agent_before_settle` 用内核 `closing` 判 verdict；`ok` / `insufficient` → 放行（`insufficient`
   只记账，不打扰用户）。
2. `contradicted` 且本回合续跑次数 `< 1` → 往 `event.entries` 追加一条
   `custom_message`（`customType:"reflex.verdict"`，内容 = 可执行的反证清单 + 期望动作），
   返回 `continue:true`。**必须**同时追加非 assistant 条目，否则 `canContinue` 为假、续跑被丢弃（PI §4.4）。
3. 第二轮无论结论如何都放行，账本记 `closing:unresolved`。绝不无条件 `continue`（无宿主熔断，PI §4.4）。
4. 语义差写进 README：Claude Code 是「不通过不许结束」，pi 是「不通过再给一次机会，然后记账放行」。

### 2.5 `harness-reflex hook <event>` CLI 契约

```
harness-reflex hook <event>        # event ∈ pretooluse|posttooluse|postfailure|stop|substop|sessionstart|sessionend
  stdin   : 宿主原始事件 JSON（不加 wrapper，便于用真实录制事件回放）
  env     : HARNESS_REFLEX_STATE_DIR  状态根
            HARNESS_REFLEX_MODE       off|observe|active（缺省 active，config 可覆盖）
            HARNESS_REFLEX_CLOCK      ISO 时间，测试用固定时钟
  stdout  : 只输出协议 JSON；诊断一律 stderr
  exit    : 0 = 正常（决策以 JSON 表达）；非 0 仅表示「已放弃」，宿主按 F1/F2 放行
```

硬约束：① stdout **永远**不能出现非 JSON 字节（会被当作 deny reason 拼进模型上下文）；
② 任何异常都 exit 0 + `{}`；③ 幂等——`dedupeKey = sha256(session_id + event + tool_use_id + tool_name +
input_digest)` 命中则直接 `{}`，防 hook 重试导致双剪枝/双阻断。

## 3. 状态与存储（hook 无状态进程的关键难点）

### 3.1 为什么必须有外部载体

- Claude Code 的 command hook **每次都是新进程**，事件之间没有任何共享内存（CC §2.1/§2.7）；
  `Stop` 里要用的「本轮工具证据」必须由先前的 hook 落盘，`transcript_path` 异步且可能滞后（CC §7 抓手3）。
- pi 扩展是进程内，可以放内存，但 `session_shutdown` 后 `/reflex-ledger` 与面板要能读同一份账本（PI §2.4），
  所以统一抽象成 `StatePort`，两套实现：`FileStateStore`（hook 进程）/ `MemoryStateStore`（进程内）。
- DSH 已有 per-agent `AgentState`，其 `StatePort` 实现就是内存 + session log 投影。

### 3.2 目录布局

```
$HARNESS_REFLEX_STATE_DIR                    # 默认 ${XDG_STATE_HOME:-~/.local/state}/harness-reflex
└── sessions/
    └── cc-3f9a1c2b7d4e5f60/                 # sha256(harness + "\0" + session_id)[:16]（防路径穿越）
        ├── meta.json        {harness, sessionId 明文, createdAt, harnessVersion, mode}
        ├── state.json       派生缓存：{turnNo, appliedSignatures[], budgets{}, continues{}}
        ├── events.jsonl     追加：每次工具事件一行（停滞窗口 / 证据组装的唯一来源）
        ├── ledger.jsonl     追加：决策与节省（权威账本，DSH 同 schema + harness 字段）
        ├── originals/<digest>.txt   剪枝原文（locator = digest + 行区间）
        ├── lock/            mkdir 原子锁（内含 pid + 起始时间）
        ├── corrupt-<ts>.log 解析失败行的隔离副本
        └── ../orphans/<hash>/   目录名与 meta 不一致的会话目录迁入此处，等人读，不自动删
```

**放哪、为什么这么放**：用户态（`XDG_STATE_HOME`）而不是项目目录——`.reflex/` 已用于项目级账本，
把它塞进仓库会污染 git；而 Claude Code 的 `${CLAUDE_PLUGIN_DATA}` 有容量与生命周期约束（CC §7 抓手2 提到
`$.store` 4 MiB / `$.fs` 单文件 4 MiB），不适合当剪枝原文仓库。用 `HARNESS_REFLEX_STATE_DIR` 可整体迁移到
插件 data 目录，作为「小体积、随插件卸载清理」的备选部署形态。

### 3.3 写协议：日志追加优先，状态只是缓存

| 数据 | 写法 | 并发安全 | 备注 |
|---|---|---|---|
| `events.jsonl` / `ledger.jsonl` | `appendFileSync`，单行 ≤ 4 KiB，一次 write | **天然并发安全**（O_APPEND 单写原子） | 权威数据；读取用尾部 N 行，绝不整文件载入 |
| `originals/<digest>.txt` | `wx` 独占创建（同名即已存在，视为成功） | 安全 | 内容不可变，天然幂等 |
| `state.json` | `state.json.tmp` → `fsync` → `rename` | 读改写需 `lock/` | Windows 上 rename-over-existing 可能失败 → unlink 重试 |
| 预算扣减 | 先 `lock/`（mkdir 原子），再读改写 | mkdir 锁 + 5 s stale 判定 | 拿不到锁 → **跳过本回合判定**并记 `skippedLockContention` |

两条决定性规则：

1. **预算是抑制旋钮，不是正确性前提**。拿不到锁/写失败时，宁可这回合不判定，也不阻塞工具调用。
2. **`state.json` 永不是权威**：删掉它、损坏它、落后它，都能从 `events.jsonl` + `ledger.jsonl` 重算。
   这一条把「并发丢更新」从正确性问题降级成性能问题。

### 3.4 并发、回合号、清理、损坏恢复

- **并发模型**：同一事件的多个 handler 并行、工具调用也可并行（CC §2.1/§6.1；PI §3.2 兄弟调用会交错）。
  因此同 session 目录会被多进程写：日志并行追加、`state.json` 由锁串行、读取允许脏。
- **回合号**：Claude Code 的事件里**没有** turn 号，唯一可靠的回合边界是 `Stop`。故 `turnNo` 只在
  `stop`/`substop` 子命令里 `++`，其他事件只读；per-turn 预算在 `Stop` 写入时重置。
  pi 侧对应 `turn_end`。
- **清理**：`sessionend` + `sessionstart` 时 gc `mtime > 7d` 的会话目录；`harness-reflex ledger gc` 手动可跑。
  单会话 `originals/` 上限 32 MiB，超限按 mtime LRU 删除并记 `retention:"evicted"`——被驱逐后的剪枝
  **降级为「只缩减不留存、不计 saved」**（与 DSH 的审计纪律一致，不产生无法还原的 locator）。
- **损坏恢复**：JSONL 逐行 `try/parse`，坏行进 `corrupt-*.log` 并继续；某文件坏行 > 5 则整份作废重算；
  `state.json` 损坏直接删除重算；`meta.json` 与目录名不一致（session_id 哈希不匹配）则整目录迁入 `orphans/`。
- **安全**：目录 0700、文件 0600；`session_id` 只用于哈希，明文只在 `meta.json`；路径分隔符与 `..`
  在家目录之外一律拒绝；任何进入模型可见文本的内容只含 digest 与文件名，**不含绝对路径**（避免泄露本机布局）。
- **可测试性**：`HARNESS_REFLEX_STATE_DIR` + `HARNESS_REFLEX_CLOCK` 让「并发写 / kill -9 / 损坏文件 /
  时钟回拨」四类场景都能用子进程夹具复现。

## 4. 实现分片与顺序

### 4.1 五个切片

| 切片 | 范围 | 验收方式（可执行） | 风险 |
|---|---|---|---|
| **S1 内核抽取 + 端口**（中） | 把 `interventions.ts` 的判定/三态/预算抽到 `core/`；新增 `core/{policy,judge,closing,evidence,prune-plan}.ts` 与 `ports/`；DSH 适配层改为消费内核（行为零变化） | `npm run build:all` exit 0；`npm test` 113/113、`test:plugin` 419/419 **零回归**；新增内核单测 ≥ 20；**架构依赖测试 1 条**（禁止 `core → adapters/state`、禁止 adapter 互引）；mutation-check 通过 | 中（大范围搬迁但语义不变） |
| **S2 `hook` 子命令 + FileStateStore**（高） | §2.5 契约 + §3 全部写协议与恢复；先只用 mock 后端 | 夹具 12 例：正常/无决策/坏 JSON/超大 stdin/信号中断/超时/重复投递（幂等）/`stop_hook_active`/三态各一；**50 并发进程写同一 session**，`ledger.jsonl` 行数守恒且每行可解析；`kill -9` 后重放不丢不重；损坏文件 3 例仍能出决策 | **高**（并发与原子写） |
| **S3 Claude Code 三件套**（最高） | plugin 目录 + mod + settings hooks + `.mcp.json`；剪枝/停滞/纠偏 active，收尾核验默认 observe | `claude plugin validate` 通过；`claude -p` 脚本 e2e：Stop block 一次（含 `stop_hook_active` 第二次放行）、PostToolUse 剪枝后模型可见长度下降且 locator 可还原；**observe 模式与关闭态 diff=0**；hook 崩溃注入后仍放行且账本记 error | **最高**（见下） |
| **S4 pi extension**（中） | §2.4 的包、5 工具、`/reflex-ledger`、三个自动能力 | `pi --extension ./dist/ext.js --help` 加载成功（已证 jiti 免构建）；`tool_result` 剪枝前后字符数断言；`agent_before_settle` 只续跑 1 次（第 3 次调用不 continue）；`tool_call` block 后模型收到 reason | 中（API 1.x 仍有 breaking，PI §8） |
| **S5 模型面 + 观察面**（低） | pi 虚拟模型 `reflex/auto`（默认关）、Claude mod 的 `turn.step` effort（opt-in）；`harness-reflex ledger --session` | 同一份 `ledger.jsonl` 输入 → CLI 摘要与 DSH 面板数字**逐字段相等**（口径一致性测试）；effort 越界按模型词表 clamp | 低 |

**风险最高：S3**。理由：① 同一插件要同时踩三个载体，任一版本门槛（mods v2.1.287、`onFailure` v2.1.295、
`PreModelSwitch` v2.1.251）都改变可用面（CC §6.1）；② 企业策略可整体关门（`disableAllHooks`、
`allowManagedHooksOnly`、`--safe-mode`），作者不可控（CC §6.4）；③ 8 次 Stop 上限 + WSL 桌面不加载 plugin，
让「装了就一定生效」不成立（CC §1.3/§2.4）；④ 无法在 CI 完整验证（需要真实 `claude` 二进制与模型凭据），
只能靠「脚本化 `-p` e2e + observe diff=0」逼近。S2 的并发风险虽高，但它是**纯本地、可完全自动化验证**的风险。

### 4.2 MVP 定义（最小可发布范围）

> **MVP = S1 + S2 + S3 的闭环**，一个安装包、一份状态、一个账本，四项干预里有三项真正生效。

包含：

- 自动层：**剪枝 active**、**停滞 active**、**失效纠偏 active**、**收尾核验默认 observe**（opt-in 可 active）；
- 工具面：根包 8 个 `reflex_*` MCP 工具**原样不动**（不新增、不改契约）；
- 账本：`ledger.jsonl` 落盘 + `harness-reflex ledger --session <id>` 可读（含 `saved` 只在留存成功时出现）；
- 三态：`off / observe / active`，`observe` 保证**零模型可见变化**（这是发布前必须验证的一条）。

不包含：虚拟模型、思考等级、设置面板、pi 载体、Windows 原生、云会话、子代理隔离域。

MVP 发布判据（可逐条验收）：① 测试与负向对照全绿；② 真机 observe diff=0；③ 判定后端人为抛错仍放行并记账；
④ 卸载后不新建状态目录、不留残留进程；⑤ 未引入任何运行时依赖（根包 `package.json` 现无 `dependencies`）。

### 4.3 建议先做哪个 harness：**Claude Code**

1. **它逼出最难的路**：无状态 hook + 外部存储 + 输出编码。先做它，内核抽象会在最苛刻的约束下成型；
   反过来先做 pi（进程内、可放内存）会把内存假设固化进内核，之后为 Claude Code 返工。
2. **风险前置**：S3 是风险最高项，按「最高风险先验证」排序，它决定 v0.2.0 能不能发布；pi 无论何时做都不阻塞发布。
3. **可交付性最强**：三件套可分别验证（MCP 工具面 → mod → hooks），每一步都有独立可观测产出。
4. **pi 成本最低**：S4 只需 ~600–900 行适配层 + 复用内核（§2.2 的 20%–25%），放在后面做的**边际成本最小**；
   且它没有硬闸，晚做不影响「防护」这个核心卖点。

## 5. 不做什么（本轮明确排除）

| 不做 | 理由 / 依据 |
|---|---|
| 撤销 Claude Code 上**已发生**的副作用 | `PostToolUse` 只能改模型看到的内容，文件/命令/网络副作用已发生（CC §2.3/§8-3） |
| 在 pi 上做**硬否决收尾** | `agent_before_settle` 无 veto，只有 `continue:true`（PI §4.4/§10-1）；只做「续跑一次 + 记账放行」 |
| 做任何**设置面板 UI** | Claude Code 无 UI 载体（CC §1.1/§6.3）；pi 只有 TUI 内联 `ctx.ui`（PI §2.4）；DSH 面板复用既有，不新做 |
| 用 MCP 影响模型 / 思考等级 | 官方无此能力（CC §4.2/§8-2）；Claude 侧只有 mod `turn.step` |
| 改写已流式产出的 token（pi） | `provider_stream_event` 只读（PI §10-2） |
| 替换 pi 内置 MCP 客户端 | 无需求；调用同走 `tool_call`/`tool_result` 管线即可（PI §6.2） |
| 做按 agent/attempt 的隔离域（pi） | 事件载荷无 `agentId/attemptId`（PI §7.3-2/§10-3）；只用 session + `toolCallId` 做 key |
| Windows 原生首发支持 | hooks 依赖 Git Bash，缺失时 PreToolUse 会**阻止调用**（CC §6.1/§6.3）；首发只保 Linux/macOS/WSL2，Windows 标 experimental |
| 支持 pi 1.4.0 之外的版本 | 1.x 频繁 breaking（PI §8）；钉死 `@earendil-works/pi-coding-agent@1.4.0`，事件适配集中在一个文件 |
| 云端 / Remote Control 会话 | 云会话不读本地 settings（CC §1.3），无法保证状态目录存在 |
| 改根包 8 工具契约 / 改版本号 | 本目标只写设计；0.2.0 版本号由发布流程决定，不在设计里动 |
| 引入运行时依赖 | 根包当前零 `dependencies`；原子写/哈希/JSONL 全部用 `node:fs` + `node:crypto` 实现 |
